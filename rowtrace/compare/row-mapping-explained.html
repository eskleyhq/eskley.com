Technical explainer

Why can't Smartsheet's backup map attachments to rows?

Because the export doesn't write down what the API already knows. Every attachment Smartsheet stores carries a reference to its parent: a row, a comment or the sheet itself. The backup drops that reference and puts every file in one folder. Rowtrace keeps it.

What does the API return?

Each attachment record names its parent, and for a row attachment the parent is the row.

GET /sheets/{sheetId}/attachments lists every attachment on a sheet:

{
  "name": "master-services-agreement.pdf",
  "parentType": "ROW",
  "parentId": 4583173393803140,
  "attachmentType": "FILE",
  "sizeInKb": 842
}

parentId is the row. That one field is the whole mapping.

What trips up a home-made script?

Three things: files attached to comments, multi-contact columns, and earlier versions.

Files attached to comments

A file attached to a comment belongs to the comment, not the row. To file it under the right row you have to read the sheet's discussions and follow the comment to the row it sits on.

Multi-contact columns

Read a sheet without level=2 and a multi-contact column comes back as plain text with its options stripped.

Earlier versions

Each version of an attachment is its own record. To keep the history you ask for the versions explicitly; the sheet only shows the current one.

What does Rowtrace do with it?

It files each attachment under its row, writes a manifest pairing every file with its row, and checks every file it writes.

For each sheet you choose, Rowtrace reads the attachment list, files each attachment in a folder for its row, exports the sheet to Excel, and writes a manifest pairing every file with its row and what the row said at the time. After the first backup, a sheet whose version hasn't moved is carried forward from the last backup instead of downloaded again. When it has moved, Rowtrace rereads the attachment list and downloads only what's new.

Every file is checked after it's written: a downloaded file against the size Smartsheet reported, a carried-forward file against the size the last backup recorded. The result is the first line of every backup's manifest.

What are your options?

Write it yourself, pay a backup service, or run Rowtrace.

Write your own script

The API gives you everything above. You also own paging, rate limits, retries, scheduling, checking and upkeep, including after whoever wrote it moves on.

Use a backup service

ProBackup and FluentPro run in their own cloud, so your computer doesn't need to be on, and both restore into Smartsheet. Each holds an authorisation to your account, and the copy of your data sits in ProBackup's AWS, or in FluentPro's Azure or your own. How they compare.

Run Rowtrace

The mapping, scheduling and checking are done, on your computer, into your folder. No restore yet.
